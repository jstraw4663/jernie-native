Jernie · Adding to a trip

One box that tries first,
and a form that finishes.

Every add starts in the same sheet, from any of the seven entry points. The magic field takes a flight number, a hotel, a restaurant, a code or a link, asks for the one thing it cannot infer, and answers with a card. The type row underneath never disappears, so a miss is not a dead end — it is the same screen with empty fields. Stops get their own sheet, because they move dates.

04 Getting from one to many

The tray belongs at the end of onboarding, where somebody has four confirmations in their inbox. The question is how the everyday sheet reaches it. Three ways, and what each one costs.

1a No mode at all

Add commits the item and the sheet stays open, field empty, with a quiet strip: Added Delta 2214 · Undo. Type again and you have added two.

CostsEach Add writes immediately, so there is no batch to review and no cross-item date sorting.
SuitsTwo or three items on a known day.
1b A switch in the header

One · Multiple as a segmented control beside the context chip. Multiple turns the field multi-line and reveals the tray.

CostsA mode to explain, in the busiest part of the sheet, that most sessions never touch.
SuitsPeople who already know they have a pile to enter.
1c It grows into the tray Recommended

The card gets a second, quiet action beside Add: Add and keep going. Take it and the card slides into a Ready to add list, the field re-arms, and the button becomes Add 2 items. Same sheet, same growth rule, no mode announced anywhere.

CostsTwo actions on the card instead of one — solved by weighting: filled Add, plain-text keep going.
SuitsBoth. And it is the same tray onboarding ends with, so one component ships twice.

What carries over to onboarding
Multi-line field, same parser
One booking per line. Each line resolves into its own card in the same list, so the everyday sheet and the wizard step differ by one attribute.
The forward address lives under the tray
A per-trip inbox address, copyable, shown wherever the tray is. Parsed mail arrives as tray cards for review rather than straight into the itinerary — same review card, different trigger.
Cards that cannot be placed ask inline
Amber card, one question, guesses as taps. It never blocks the others from being written.
One undo for the batch
Add 3 items writes once and offers one undo, not three toasts.

Rules
The query never moves. Field stays pinned under the chip at every height; results and fields grow beneath it.
Add turns on when title, type, day and stop are all true. Amber fields never gate it.
Unpicked types dim to 42%, never disappear — one tap corrects a wrong guess.
Lookup is debounced 350ms and shows a skeleton card at the height the real one will take, so nothing jumps.

Share sheet · pasteThe link, already in the field
Open for the backend conversation
Flight lookup needs a schedule source that answers by number and by route. The design assumes it can return several dates for one number.
Place search needs name, category, hours, coordinates and rating in one response — hours drive the two time guesses on the Eat card.
Link unfurling and email parsing return the same shape as a search hit, so both land on the review card unchanged.
Every parsed field needs a confidence flag: it decides mono versus grey, and which single question the sheet asks.
