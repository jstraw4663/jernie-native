**Branch:** `feat/session-7-explore`, from `feat/design-system` @ `d5b65af`.

## What the canvas specifies, and where the screen is today

`app/(trips)/[tripId]/(tabs)/explore.tsx` predates the redesign. Every one of its six feature
components builds its styles at module scope off the static `Core` palette, so none of them
can follow the theme. The structural gaps against the canvas:

| Canvas | Today |
| --- | --- |
| One filter bar: stop bubble, type bubble, a sliders button with a count badge | A search field, then two stacked `FilterPillRow` scrollers |
| Exactly one carousel — *"One carousel maximum per screen"* | Up to six `PlaceCarouselRow`s |
| A two-column grid below it | A single-column list of bordered rows |
| Bubbles open an inline dropdown; the sliders button opens a sheet with Apply | No dropdowns, no sheet |
| Filter state shared with Map, surviving a tab switch | Four `useState`s local to the screen |
| Stop defaults to where you are | Defaults to `'all'` — the exact thing the gate forbids |

## Decisions taken with Jeremy before this plan

1. **No save button.** Every card in the canvas carries a save circle. There is no
   saved-places concept in the schema and redesign work may not add one, so the circle is
   omitted this session rather than faked. Adding to the itinerary stays where it is: tap a
   card, the detail sheet opens, Add opens the day picker.
2. **No distance.** The canvas sorts by Distance and subtitles the carousel *"Open now,
   within 15 minutes of Atlantic Oceanside"*. 6 of 54 places in the trip snapshot have
   coordinates, `PlaceEnrichment.hours` is a free-form `string[]`, and `expo-location` is not
   installed. The sort control keeps the canvas's shape and offers the sorts the data
   supports; the carousel's subtitle states its real basis.
3. **Search moves into the filter sheet.** The canvas's Explore header has no search field.
   The capability is kept, as the first field behind the sliders button, where the Apply
   commit point already lives.
4. **`ChipDropdown` is approved as a custom component** (Task 2), with the register row
   written in the same change.
5. **The filter sheet holds search and a must-do toggle.** Nothing else — price coverage is
   category-skewed and rating coverage is uneven, so both would filter some categories well
   and silently empty others.

## Task 1 — Domain: the default stop, one featured row, and the filter model

`Tier: light | Reasoning: low - pure functions in one file against a complete spec.`

All of this is `src/domain/explore.ts`. No component imports change in this task.

**1a. `getExploreDefaultStopId(stops: Stop[], now: Date): string | null`**

This is the gate. `getActiveStopId` in `src/domain/trip.ts` already resolves a *current* stop
but falls through to the last stop whenever today is not inside one — which is wrong for a
traveller sitting in a gap between two stops, and is the reason Explore could never default
honestly. The new function, in that order:

1. the stop whose span contains today — `todayIso >= s.dates.start && todayIso < s.dates.end`,
   matching `getActiveStopId`'s end-exclusive convention exactly;
2. otherwise the **earliest stop that starts after today** — the next one, which covers both
   pre-trip and between-stops;
3. otherwise the last stop — the whole trip is behind you;
4. `null` only when `stops` is empty.

Do not change `getActiveStopId`. Its post-trip behaviour is correct for its own callers, and
the two functions differ only in step 2.

**1b. The filter model**

```ts
export interface ExploreFilters {
  stopId: string | 'all';
  category: FilterId;
  search: string;
  mustOnly: boolean;
  sort: SortKey;
}
```

Add `matchesMustFilter(place: Place, mustOnly: boolean): boolean` and
`matchesFilters(place: Place, f: ExploreFilters): boolean` composing the four existing
predicates plus the new one. Add `sheetFilterCount(f: ExploreFilters): number` — the badge on
the sliders button — counting only what the sheet owns: `+1` when `search.trim()` is
non-empty, `+1` when `mustOnly`. Stop, category and sort never count; they have their own
visible controls.

**1c. One featured row**

Delete `buildCarouselRows`, `CarouselRowDef`, `CarouselRow`, `PINNED_ROW` and
`SHUFFLEABLE_ROWS`. The spec's rule is *"One carousel maximum per screen"*, so the six-row
builder has no caller left.

```ts
export const FEATURED_LIMIT = 12;
export function buildFeaturedPlaces(
  places: Place[], filters: ExploreFilters, shuffleSeed: number,
): Place[]
```

The must-do places passing `matchesFilters`, seeded-shuffled by the existing 4-hour seed,
capped at `FEATURED_LIMIT`. Keep `seededShuffle` and `getShuffleSeed` unchanged — both are
tested and both stay in use.

**1d. Sort options**

`SORT_OPTIONS` keeps its four entries but relabels to sentence case per `voice.md`:
`Top rated`, `Price, low first`, `Price, high first`, `A – Z`. `sortPlaces` is unchanged.

**Tests.** Rewrite `__tests__/domain-explore.test.ts`. Keep every passing case for
`seededShuffle`, `getShuffleSeed`, the four predicates, `sortPlaces` and the add-to-itinerary
helpers. Replace the `buildCarouselRows` cases with `buildFeaturedPlaces` ones. Add
`getExploreDefaultStopId` cases covering all four branches — inside a stop, in a gap between
two stops, before the trip, after the trip, and empty. Add `sheetFilterCount` cases for 0, 1
and 2. The suite must not import anything from `src/features/`.

## Task 2 — `ChipDropdown`

`Tier: standard | Reasoning: medium - anchor measurement, a Modal, and the accessibility contract.`

New `src/ui/ChipDropdown.tsx`. **Approved as custom** — the register row is part of this task.

The spec is explicit: *"Tap bubble — inline dropdown, not a sheet. Selection applies
immediately, no Apply button."*

```ts
export interface DropdownOption { id: string; label: string; icon?: ReactNode; }
export interface ChipDropdownProps {
  label: string;                 // the chip's own text — already resolved by the caller
  options: DropdownOption[];
  selectedId: string;
  onSelect: (id: string) => void;
  icon?: ReactNode;              // leading icon inside the chip
  testID?: string;               // options get `${testID}-option-${id}`
}
```

- The trigger is `src/ui/Chip` with `variant="dropdown"`, unmodified. Do not restyle it, and
  do not set `selected` — a bubble that always has a value is not a selection state.
  `hitSlop` of 5 brings the 34px chip to the 44px minimum.
- On press: measure the trigger with `onLayout` + `measureInWindow`, then open a
  `Modal` (`transparent`, `animationType="none"`) whose backdrop is a full-screen `Pressable`
  that dismisses. The card is absolutely positioned under the trigger's frame, left-aligned to
  it, flipped above when it would cross the screen's bottom inset.
- Card: `t.surface`, `Radius.row`, `Shadow.float`, `minWidth: 180`,
  `maxHeight: 320` with a `ScrollView` inside. **A shadow, so no border** — the system's rule.
- Each option is a `Pressable` at `Layout.tapMin` tall, `Gutter` horizontal padding,
  `Typography.roles.body`. The selected one takes `t.action` ink and a trailing `Check` glyph
  at 14px — not a fill, because a 9% fill inside a floating card reads as a hover state.
- Press is `PRESSED_OPACITY` + `tap()`. Selecting calls `onSelect` and closes.
- Entry is `Animation.springs.gentle` on opacity and a 4px translate — the same spring `Chip`
  already uses, so the bubble and its menu move as one object.
- `accessibilityRole="button"` with `accessibilityState={{ expanded }}` on the trigger;
  `accessibilityRole="menuitem"` and `accessibilityState={{ selected }}` on each option; the
  backdrop is `accessible={false}` and the card is `accessibilityViewIsModal`.

**Register.** Add a row to `.claude/skills/jernie-design/reference/custom-components.md`,
above the marker comment:

> `ChipDropdown` | `@react-native-menu/menu`, `react-native-element-dropdown` | The first
> renders the platform `UIMenu`, which will not take these tokens, the DM Sans faces or the
> dark palette — the same reason `SegmentedControl` and `Toggle` are ours. The second owns
> its own trigger and text styling, and the trigger here has to be `Chip` so the two bubbles
> and every other chip in the app stay one object. `@gorhom/bottom-sheet` is already the
> answer for the *filter* sheet; the spec deliberately distinguishes it from the bubbles,
> where a one-tap stop switch may not cost a sheet open and a dismiss. A measured anchor over
> a `Modal` is ~120 lines.

Also add it to `src/ui/index.ts`.

**Tests.** New `__tests__/components/ChipDropdown.test.tsx`: closed by default; pressing the
trigger renders the options; pressing an option fires `onSelect` with that id and closes; the
selected option carries `accessibilityState.selected`.

## Task 3 — `ExploreFilterContext`, the shared store

`Tier: standard | Reasoning: medium - provider placement and the default-derivation rule.`

This is the half of the gate the roadmap names first, and Session 8's Map consumes it
unchanged.

New `src/contexts/ExploreFilterContext.tsx`:

```ts
export function ExploreFilterProvider({ children }: { children: ReactNode })
export function useExploreFilters(): {
  filters: ExploreFilters;
  setStop:     (id: string | 'all') => void;
  setCategory: (id: FilterId) => void;
  setSearch:   (q: string) => void;
  setMustOnly: (on: boolean) => void;
  setSort:     (s: SortKey) => void;
  reset: () => void;
}
```

- Mount `ExploreFilterProvider` in `app/(trips)/[tripId]/(tabs)/_layout.tsx`, inside the
  existing `AdminUnlockProvider` and above `<Tabs>`. `TripProvider` already sits above this
  layout in `app/(trips)/[tripId]/_layout.tsx`, so the provider can read `stops` from
  `useTripContext()`, and every tab — including the Map route Session 8 adds — is under it.
- **The default.** Initial `stopId` is `getExploreDefaultStopId(stops, new Date())`, falling
  back to `'all'` only when it returns `null`. `stops` arrives asynchronously, so re-derive in
  an effect when the stop list changes **from empty to populated** — and never after the user
  has chosen a stop. Hold a `userChoseStop` ref that `setStop` sets; once true, the effect
  stops touching `stopId` for the rest of the session. Without that ref a late RTDB update
  silently throws away the traveller's choice.
- `'all'` stays a legal *choice* — the dropdown offers "All stops" — but is never the default
  while the trip has stops. That is the whole of *"never 'anywhere' with a trip"*.
- Not persisted. MMKV is named for *"last-used filters"* in the mapping, but a stop that
  defaults to where you are is wrong the moment you sleep somewhere else, and reviving a
  three-days-stale filter set is worse than deriving a fresh one. In-memory for the session.
- `useExploreFilters` called outside the provider throws with a named message, matching
  `useTripContext`'s existing shape.

**Tests.** New `__tests__/contexts/ExploreFilterContext.test.tsx`: defaults to the current
stop; defaults to the next stop when today is in a gap; re-derives when stops arrive late;
does **not** re-derive after `setStop`; `reset` returns to the derived default, not to `'all'`.

## Verification of the gate itself

The roadmap's Session 7 gate is *"Filter state lifted into a shared store. Stop defaults to
current/next, never 'anywhere' with a trip."* It is green when:

1. `ExploreFilterProvider` sits above `<Tabs>` and every filter setter writes to it — so
   Session 8's Map consumes the same object with no further lifting.
2. `getExploreDefaultStopId` resolves current → next → last, and `'all'` is only ever reached
   by an explicit user choice or by a trip with no stops.

## What to test on device, and how

**The default stop**
- Open Explore mid-trip: the stop bubble reads today's stop, never "All stops".
- Open it on a day between two stops — a travel day: it should read the **next** stop, not
  the last one.
- Open a trip that has finished: the last stop.

**The shared store (the gate)**
- Set the stop to a different city and the type to Hikes, leave Explore, come back: both hold.
- After Session 8 lands, the same switch to Map must arrive on the same result set.
- Force-quit and relaunch: filters reset to the derived default. That is deliberate — a stale
  stop is worse than a fresh one.

**The filter bar**
- Tap the stop bubble: a menu appears **under** it, not a sheet from the bottom. Tapping an
  option applies immediately and closes.
- Open a bubble near the bottom of the screen: the menu flips above the chip rather than
  running off-screen.
- Tap the sliders button, type a search, Apply: the badge reads 1. Add must-do: 2. Clear
  both: the badge disappears.
- Open the sheet, type, then swipe it away without Apply: nothing changed.

**The screen**
- Exactly one carousel. If you can see two, Task 6 regressed.
- Filter to something with fewer than two must-dos: the carousel section disappears entirely
  rather than showing one card.
- Filter to nothing at all: a `PromptRow` offering "Clear filters", not a grey sentence.
- A place already on the itinerary shows "Added" in teal under its name in the grid.

**Both themes and accessibility**
- Dark mode: every surface follows. Any component still on `Core` will stay white — that is
  the tell.
- VoiceOver: the bubbles announce as buttons with an expanded state; each menu option
  announces as selected or not; the sliders button announces "Filters".
- Largest Dynamic Type: card names and the two section headers stay readable, and the grid's
  two columns do not collide.

**Findings the reviews caught, and what changed:**

- `getExploreDefaultStopId` trusted array order in its next-stop and last-stop branches. It
  now sorts a copy, so it cannot inherit `getActiveStopId`'s unstated precondition.
- `ChipDropdown` had no horizontal clamp — a right-anchored card ran ~85px off a 390pt
  screen, which Task 6's sort control would have hit. And `Chip`'s internal `Pressable` kept
  its role and label even when disabled, so VoiceOver announced every bubble twice.
- `ExploreFilterBar` carried three setter props it never called; the brief's "five setters"
  was wrong, not the implementation.
- `ExploreFilterSheet` shipped without a heading, unlike every other sheet in the app.
- `ExploreFilterContext` read `new Date()` where the rest of the app reads `getDevNow()`, so
  the admin panel's time override would not have moved Explore's default stop.
