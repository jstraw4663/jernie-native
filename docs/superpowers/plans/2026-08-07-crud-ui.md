# Phase 2 — CRUD UI + Chronological Stop Ordering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Phase 1's CRUD layer reachable from the app — add/edit/delete stops, bookings, itinerary items, and trips — and display stops in date order rather than creation order.

**Architecture:** Phase 1 built the write layer (`useBooking`, `useEditStop`, `itineraryWrites`, `domain/cascade`); nothing imports it. This phase builds the UI that calls it, following the established three-layer split already in the codebase: a presentation-only form component (no RTDB, no sheet knowledge — see `StopForm.tsx`), a `BottomSheetModal` wrapper that owns the write call (see `AddStopSheet.tsx`), and screen-level wiring that holds the sheet ref. Trip deletion is a soft `deletedAt` marker plus a restore path, not a hard delete.

**Tech Stack:** React Native + Expo SDK 56, Expo Router v4, TypeScript strict, `@gorhom/bottom-sheet` v5, `react-native-calendars`, `@react-native-firebase/database` (RTDB), Jest + `@testing-library/react-native`.

**Spec:** `docs/superpowers/specs/2026-08-07-crud-ui-design.md`

## Global Constraints

- **Direct RTDB writes only.** Do NOT use `src/lib/writeQueue.ts`. Match Phase 1's style.
- **`await authReady` first** in every new write function (import from `@/src/lib/firebase`).
- **`stripUndefined`** (`@/src/utils/stripUndefined`) wraps every patch/optional-field object before `.set()`/`.update()`. RTDB rejects `undefined`; `null` is meaningful and must survive.
- **Colors stay fixed to the stop.** Never recompute or renumber `stop.order`. It is a color-palette index (`resolveStopColor(pack, order)`) and creation-order tiebreak only.
- **Every destructive action** (remove stop/booking/trip/itinerary item) goes through `confirmDelete` from Task 2. No bare `Alert.alert` calls, no unconfirmed deletes.
- **Form components stay presentation-only** — no RTDB imports, no bottom-sheet imports. They take `onSubmit` and surface rejections inline. `StopForm.tsx` is the reference.
- **Sheet components** follow `AddStopSheet.tsx` exactly: `React.forwardRef` + `useImperativeHandle` exposing `present()`/`dismiss()`, `useSheetContext()` increment/decrement in `onChange`, `BottomSheetBackdrop`, `useBottomSheetSpringConfigs({damping:60, stiffness:180, mass:1.2, restDisplacementThreshold:0.01, restSpeedThreshold:0.01})`, `enableDynamicSizing`, `BottomSheetScrollView` with `keyboardShouldPersistTaps="handled"`.
- **Design tokens only** (`@/src/design/tokens`) — no raw hex, no raw spacing numbers. Use `hexWithAlpha` from `@/src/utils/colors` for alpha variants.
- **After any write, call `refetch()`** from `useTripContext()`. `useTripData` is fetch-once, not a live listener.
- **Run `npx jest` before every commit.** Output must be pristine — no warnings.

/**
 * Display order for stops: chronological by date, NOT by `order`.
 *
 * `order` is assigned as `max(order)+1` at creation (see useAddStop), so sorting by it
 * shows stops in the sequence they were typed in — wrong the moment someone adds a stop
 * that falls between two existing ones. Dates are YYYY-MM-DD, so string comparison is
 * chronological.
 *
 * `order` survives only as the final tiebreak, and remains the stop's color-palette index
 * (see getStopColor) — sorting never renumbers it, so a stop keeps its color for life.
 */
export function compareStopsChronologically(
  a: Pick<Stop, 'dates' | 'order'>,
  b: Pick<Stop, 'dates' | 'order'>,
): number {
  return (
    a.dates.start.localeCompare(b.dates.start) ||
    a.dates.end.localeCompare(b.dates.end) ||
    a.order - b.order
  );
}
```

import { Alert } from 'react-native';

export interface ConfirmDeleteOptions {
  title: string;
  message: string;
  /** Defaults to "Remove". Use a more specific verb where it reads better, e.g. "Delete trip". */
  confirmLabel?: string;
  onConfirm: () => void;
}

/**
 * The single confirmation gate for every destructive action in the app (remove stop,
 * booking, itinerary item, trip). Cancel is first and is the safe default; the confirm
 * button is styled `destructive` so the platform renders it in red.
 */
export function confirmDelete({ title, message, confirmLabel = 'Remove', onConfirm }: ConfirmDeleteOptions): void {
  Alert.alert(title, message, [
    { text: 'Cancel', style: 'cancel' },
    { text: confirmLabel, style: 'destructive', onPress: onConfirm },
  ]);
}
```

Create `src/lib/tripWrites.ts`:

```typescript
import { database, authReady } from '@/src/lib/firebase';
import { stripUndefined } from '@/src/utils/stripUndefined';
import type { Trip } from '@/src/types';

export type TripPatch = Partial<Pick<Trip, 'name' | 'pills'>>;

/** Owner-only per RTDB rules (`name`/`pills` each carry an ownerUid check). */
export async function updateTrip(tripId: string, patch: TripPatch): Promise<void> {
  await authReady;
  await database().ref(`trips/${tripId}`).update(stripUndefined(patch));
}

/**
 * Soft-delete: stamps `deletedAt` so the trip drops out of the user's active list while
 * all of its data stays intact and restorable. There is no hard delete — RTDB rules make
 * `trips/{tripId}` create-only, and a shared trip's other members would lose it silently.
 */
export async function archiveTrip(tripId: string): Promise<void> {
  await authReady;
  await database().ref(`trips/${tripId}`).update({ deletedAt: Date.now() });
}

export async function restoreTrip(tripId: string): Promise<void> {
  await authReady;
  await database().ref(`trips/${tripId}`).update({ deletedAt: null });
}
```
